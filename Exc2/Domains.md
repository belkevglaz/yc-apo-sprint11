## Домены данных

1. **Клиентский домен** (Customer Domain)
   Включает всю информацию о клиентах компании, их профилях и взаимодействии с системой

    **Основные данные:**
   - Персональная информация клиентов (ФИО, контактные данные).
   - Финансовая история клиента.
   - Информация о посещениях клиник.

   **Особенности:**
     Данные должны быть защищены (в соответствии с законодательством о защите персональных данных, например, ФЗ-152).


2. **Медицинский домен** (Medical Domain)
   Обрабатывает медицинские карты, истории болезни, результаты исследований и назначения врачей.

   **Основные данные:**
   - Истории болезни.
   - Медицинские исследования.
   - Назначения врачей.

   **Особенности**:
   Данные медицинского домена не включаются в аналитические витрины и используются только внутри домена.  

   
3. **Финансовый домен** (Finance Domain)
   Управляет всеми финансовыми аспектами бизнеса, включая банковские услуги, счета, кредиты и финансовую отчётность.

   **Основные данные:**
   - Данные о счетах и транзакциях.
   - История кредитов клиентов.
   - Финансовая отчётность.

   **Особенности**:
   Требует высокой доступности и интеграции с банковскими регуляторами


4. **Инвентаризационный домен** (Inventory Domain)
   Отвечает за управление запасами и инвентаризацией в клиниках и других подразделениях.

    **Основные данные:**
    - Информация о наличии медикаментов, реагентов и оборудования.
    - Списки поставок и заявок.


5. **BI и аналитический домен** (BI & Analytics Domain)
   Служит для построения аналитических отчётов и предоставления витрин данных для сотрудников.

    **Основные данные:**
    - Агрегированные данные из других доменов (с оговорками про витрины с данными из медицинского).


6. **Интеграционный домен** (Integration Domain)
   Обеспечивает взаимодействие между доменами, внешними системами и новыми бизнесами.

   **Основные данные:**
   - Шина сообщений (например, Kafka).
   - Модели данных для передачи между системами.

   **Особенности:**
   - Должен поддерживать Event-Driven архитектуру для асинхронного обмена данными.

7. **Домен поддержки данных** (Data Lakehouse Domain)
   Обеспечивает поддержку и сопровождение инфраструктуры Data Lakehouse

   **Особенности**:
   - Должен поддерживать инфраструктуру "озера данных", конфигурировать и масшабировать.
   

## Преимущества подхода

- Микросервисная архитектура: Каждый домен становится отдельным набором микросервисов с автономной бизнес-логикой и базой данных.
- Data Lakehouse: DWH трансформируется в Data Lakehouse, где данные из всех доменов агрегируются для аналитики, без добавления бизнес-логики.
- Интеграция через шину: Используется Event-Driven архитектура для обмена данными между доменами и внешними системами.
- Единая платформа управления доступом: Для обеспечения безопасности и разграничения прав пользователей при работе с данными.
- Независимость доменов: Каждое направление развивается автономно без зависимости от изменений в других доменах.
- Масштабируемость: Упрощается интеграция новых бизнесов, так как они подключаются к шине данных.
- Снижение нагрузки на DWH: Аналитика переходит на витрины данных, а основная обработка логики переносится в домены.
- Гибкость и скорость изменений: Локальные изменения в одном домене не затрагивают другие.
